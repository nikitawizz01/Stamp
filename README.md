# Stamp / Печать — конструктор КП

Статичный сайт для GitHub Pages плюс Supabase: вход по почте, счётчик бесплатных скачиваний на сервере и обязательное принятие Политики конфиденциальности.

```
index.html            сайт целиком (конструктор, вход, PDF)
privacy.html          Политика конфиденциальности (EN + RU)
config.js             ваши настройки: адрес и ключ Supabase, почта
supabase/schema.sql   база данных, правила доступа, серверный счётчик
.nojekyll             чтобы GitHub Pages отдавал файлы как есть
```

## Как устроена защита счётчика

- Счётчик хранится в базе Supabase, а не в браузере. Очистка кэша, режим инкогнито, другой браузер или другое устройство его не сбрасывают.
- У браузера нет права записи ни в одну таблицу. Счётчик меняет только серверная функция `consume_download()`. Она проверяет лимит и увеличивает счётчик за одну заблокированную транзакцию, поэтому два одновременных клика тоже не пройдут.
- Лимит привязан к нормализованному хешу почты. Псевдонимы вида `name+1@gmail.com`, точки в Gmail, удаление и повторное создание аккаунта лимит не обнуляют.
- Сначала сервер списывает скачивание, и только потом браузер сохраняет файл.

Честное ограничение: PDF собирается в браузере. Человек, который разбирается в коде, может открыть инструменты разработчика и собрать файл в обход проверки. Обычный пользователь этого не сделает. Полностью закрыть эту лазейку можно только генерацией PDF на сервере — это отдельный следующий шаг.

## Запуск: 6 шагов

### 1. Создайте проект Supabase

1. Зарегистрируйтесь на https://supabase.com и нажмите **New project**.
2. Регион выберите в ЕС, например **Central EU (Frankfurt)**. Это важно для GDPR и упомянуто в политике.
3. Дождитесь, пока проект запустится (1–2 минуты).

### 2. Создайте базу

1. Откройте **SQL Editor → New query**.
2. Вставьте всё содержимое `supabase/schema.sql` и нажмите **Run**.
3. Должно появиться «Success. No rows returned».

Затем включите автоочистку. Без неё обещание «храним до 24 месяцев» в политике будет неправдой:

1. **Database → Extensions** → найдите `pg_cron` → включите.
2. В **SQL Editor** выполните строку из конца `schema.sql` (уберите `--` в начале двух строк):

```sql
select cron.schedule('stamp-purge-free-usage', '15 3 * * *',
  $$ delete from public.free_usage where updated_at < now() - interval '24 months' $$);
```

### 3. Настройте вход

1. **Authentication → Sign In / Providers → Email**: должно быть включено. Пароль пользователям не нужен — сайт использует ссылку для входа.
2. **Authentication → URL Configuration**:
   - **Site URL**: адрес вашего сайта, например `https://ваш-логин.github.io/stamp/`
   - **Redirect URLs**: добавьте тот же адрес.
3. **Authentication → Emails → Magic Link**: при желании поменяйте тему письма, например на «Your Stamp sign-in link / Ссылка для входа в Печать».

> **Важно до запуска.** Встроенная почта Supabase предназначена только для тестов: она отправляет всего несколько писем в час. Для настоящих пользователей подключите свой SMTP в **Authentication → Emails → SMTP Settings**. Например, у Resend есть бесплатный тариф. После этого впишите почтовый сервис в `privacy.html`, раздел 4.

### 4. Заполните `config.js`

В **Project Settings → API** скопируйте:

- **Project URL** → в `SUPABASE_URL`
- **anon / publishable key** → в `SUPABASE_ANON_KEY`

Этот ключ публичный по задумке: данные защищают правила базы, а не секретность ключа.
**Никогда не вставляйте `service_role` / secret key** — он даёт полный доступ к базе.

Ещё укажите `CONTACT_EMAIL` — ящик, который вы реально читаете. На него будут приходить запросы по данным.

### 5. Заполните политику

Откройте `privacy.html` и найдите все места в `[квадратных скобках]` — они подсвечены жёлтым. Их пять видов, в обоих языках:

- ваше имя или компания
- почтовый адрес
- почта для вопросов о данных
- регион Supabase и почтовый сервис
- надзорный орган (если вы в Польше — UODO)

Заполнив, удалите вокруг текста `<span class="fill">` и `</span>`, чтобы убрать жёлтую подсветку.

### 6. Опубликуйте на GitHub Pages

1. Создайте репозиторий на GitHub, например `stamp`. Он может быть публичным: секретов в файлах нет.
2. Загрузите все файлы из этой папки: **Add file → Upload files**, либо через `git push`.
3. **Settings → Pages → Build and deployment**: Source — **Deploy from a branch**, Branch — `main`, папка `/ (root)` → **Save**.
4. Через минуту сайт будет доступен по адресу `https://ваш-логин.github.io/stamp/`. Этот же адрес должен стоять в шаге 3.

Свой домен подключается там же, в **Settings → Pages → Custom domain**. После этого обновите Site URL и Redirect URLs в Supabase.

## Проверка после запуска

1. Нажмите **Download PDF** → должно появиться окно входа. Без галочки согласия ссылка не отправляется.
2. Войдите по ссылке из письма → скачайте 2 PDF → третье скачивание откроет окно Pro.
3. Откройте сайт в режиме инкогнито или в другом браузере, войдите с той же почтой → по-прежнему 0 из 2.
4. В Supabase: **Table Editor → consents** — там видна запись о принятии политики с датой.

## Обслуживание

**Выдать Pro вручную** (пока не подключена оплата) — в SQL Editor:

```sql
update public.profiles set is_pro = true, pro_until = now() + interval '1 month'
  where id = (select id from auth.users where email = 'client@example.com');
```

**Изменить политику.** Отредактируйте `privacy.html`, затем поменяйте версию в двух местах: `PRIVACY_VERSION` в `config.js` и `current_privacy_version()` в `schema.sql` (выполните эту функцию в SQL Editor заново). Все пользователи увидят окно согласия перед следующим скачиванием.

**Изменить бесплатный лимит.** Поменяйте число в `free_limit()` в `schema.sql` и выполните функцию заново. Кружки в шапке рассчитаны на 2; если лимит станет другим, поменяйте и `FREE_LIMIT` в коде.

**Удаление аккаунта.** Пользователь удаляет аккаунт сам из меню. Почта, согласия и история скачиваний стираются. Остаётся только хеш почты со счётчиком — это описано в политике.

## Ещё не сделано

- Оплата. Кнопка Pro показывает «скоро», пока в `config.js` пустой `CHECKOUT_URL`.
- Условия использования (Terms of Service) — понадобятся вместе с оплатой.
- Генерация PDF на сервере — закроет последнюю лазейку и даст PDF с выделяемым текстом.
- Шрифты загружаются с Google Fonts, это упомянуто в политике. Если хотите обойтись без передачи IP в Google, шрифты можно разместить в самом репозитории.

## Исходники

`index.html` собран из файлов в `src/`: `i18n.jsx` (тексты EN/RU), `app.jsx` (логика и интерфейс) и `style.css`. Если меняете исходники, `index.html` нужно пересобрать: склейте `i18n.jsx` и `app.jsx` и скомпилируйте JSX через esbuild (`--jsx-factory=React.createElement`). Проще всего попросить об этом Claude, приложив изменённые файлы.
